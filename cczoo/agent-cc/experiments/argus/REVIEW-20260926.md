# Argus structure and implementation review

This review covers the pending Argus multi-client, receiver, experiment and AAMAS tooling changes on top of `8be8afe`, together with their production integration points. It is a code review and local verification record; remote hardware/business results remain NOT_RUN.

## Structure changes

- Added [ARGUS.md](../../ARGUS.md) as the production/adapters/experiments code map and linked it from both Agent-CC READMEs.
- Added [STRUCTURE.md](STRUCTURE.md) for experiment command ownership and dependencies, plus the parent [experiments index](../README.md).
- Moved root `suite*.example.json`, `fault-trial.example.json` and `config/locomo.example.json` into `examples/`. Runtime fragments remain in `config/`. CLI names, flags and installed component paths are unchanged.
- Separated local `private/`, `evidence/` and `generated/` outputs from source examples and source-manifest enumeration. Test fixtures with similarly named nested folders remain included.
- Kept research/manuscript edits under `documents_ly` out of the code publication. The complete earlier manuscript change report remains in that local working area; deployment documentation has no dependency on the private draft.

The existing component boundaries remain useful: `core/argus` handles evidence; `core/spire` identity, credentials and ingress; `tc_api` controlled launch; adapters integrate the applications; experiment tools invoke or observe them. No extra package layer or generic orchestration service was introduced.

## Findings fixed

| Finding | Before | After / regression |
|---|---|---|
| Business resume state | A temporary scope preflight failure could overwrite an existing submission/task state and lose its resume path | Preserve prior intent and task journal; distinguish scope mismatch from unavailable observation; consecutive resume regression |
| Incomplete LoCoMo statistics | A hashed INCOMPLETE result in a resumable runner operation was excluded from QA statistics | Include its answered/all-task denominators and scores; execution remains UNKNOWN; reject unbound or stale receipts |
| Lifecycle observation gaps | `observer_gap` and failed samples could still produce COMPLETE coverage | Mark the lifecycle observation UNKNOWN on either gap; do not change receiver evidence into a guessed result |
| Receiver clock domains | Monotonic timestamps could be compared across unknown/different boots | Use monotonic time only within a known common clock domain; otherwise use wall time and measured uncertainty; ambiguous boundary reads remain UNKNOWN |
| Shared-service availability | An actual refused/reset HTTPS request was indistinguishable from an uninitialized probe | Native transport associates narrow connection errors with an actual request; availability reports unavailable, while delivery remains separately NOT_RUN/UNKNOWN |
| Source manifest after experiments | Local datasets/results/generated configs could alter a source-only verification | Exclude only the documented experiment output directories; source examples and test evidence fixtures stay covered |
| Operator policy wording | Older prompts described UpToDate as mandatory with a PoC exception | Record the actual approved policy and tcb_status; do not add TCB UpToDate as an admission requirement |

The connection-error classification is deliberately limited to native HTTPS `ECONNREFUSED`/`ECONNRESET`, or body reset after an actual response receipt. Configuration, credentials, Docker, timeout and TLS validation errors remain UNKNOWN. A failed business request never establishes zero received bytes.
