# Synthetic fact receipts, Quote counts, and recovery evidence

This adds experiment observation to the existing implementation. It does not
change admission policy, SVID issuance, or the nonblocking audit data path.
The 2026-10-02 focused receipt/connection/coordinator tests were executed locally;
see `tmp/argus-implementation-20261002/receipt-delivery.md` for the final count and
command. Real TDX, Linux systemd timing, remote receiver behavior and model
results remain NOT_RUN. The independent DENIED/invalid-interval qualification
oracle below is an input contract, not an implemented online oracle.

## Service preparation

Rebuild the pinned audit image using `adapters/OpenViking/receiver_audit/build.py`,
then deploy its real approved digest through the normal launch/profile path.
Add the optional setting to the deployment configuration before rendering:

```json
"receiver_audit": {
  "run_id": "trial-a",
  "mode": "on",
  "image_config_digest": "sha256:<actual-audit-image-digest>",
  "synthetic_facts": true
}
```

The launch profile sets `ARGUS_AUDIT_SYNTHETIC_FACTS=1`. Do not manually change a
running container's environment. Old deployments omit `synthetic_facts` and keep
byte-only audit behavior. `mode=off` remains the explicit overhead control.

Use the existing [collector instructions](../../adapters/OpenViking/receiver_audit/README.md)
to bind the actual application reader PID and run the independent collector.
No fact plaintext, reference values, answers or secret manifest is installed in
the service. The matcher recognizes the fixed ASCII protocol generated by
`fact_protocol.py` and validates the complete frame's embedded hash.

The application's original ASGI message is returned without waiting for a
collector ACK. Matching holds only a bounded frame-length tail per request.
Metadata datagrams retain source sequences, dropped-message counters and
watermarks. The receiver's instance comes from kernel credentials and the
protected launch/process binding; client/run/task headers are correlation only.

`fact_observed` records a complete frame's `fact_id`, `full_fact_sha256`,
`fact_bytes`, body offsets, completing chunk and actual read time. `fact_partial`
records a recognizable unfinished frame prefix and `candidate_frame_bytes`;
it is not a complete fact or a count of leaked secret bytes. HTTP body bytes,
complete frames and partial candidates are reported separately.

When replacing the target, keep the collector alive. Prepare the new protected
target record, then call its existing `add-target` control command before
releasing requests to the replacement. This registers observation, not Argus
admission. Do not overwrite the old binding or erase the old source's tail.
The collector polls original PID/starttime disappearance and emits
`source_exited`. Only times after that observation can establish that the old
reader no longer exists; the unobserved crash tail remains UNKNOWN.

## Receipt context and assessment

`fact_receipts.py` consumes the continuous task's public `manifest.json`,
`result.json`, the receiver JSONL and a small context file. It also filters a
log containing other run IDs down to the selected run; one collector per run
is required. Paths below are relative to the context file.

No-fault context (`continuous/receipt-context.json`):

```json
{
  "schema": "argus.fact-receipt-context.v1",
  "run_id": "trial-a",
  "clock_uncertainty_ms": 5,
  "admissions": [
    {"observation": "../admission-before", "sha256": "<SHA256 of admission-before/observation.json>"}
  ]
}
```

`admission-before` is a real `admission_trial.py observe` output directory,
including `target.json`. The assessor checks its actual admission, identical
before/after readiness, local target match and verified service SVID association.
This operational evidence supports the guarded-native baseline as well as Full.
Run this observation before releasing the task workload, not after it.

Fault and explicit re-admission context:

```json
{
  "schema": "argus.fact-receipt-context.v1",
  "run_id": "trial-a",
  "clock_uncertainty_ms": 5,
  "fault_file": "../server/fault.jsonl",
  "bound_ms": 7000,
  "lifecycle_file": "../server/lifecycle.jsonl",
  "storage_probe": {"path": "../server/storage-ready.json", "sha256": "<actual-file-SHA256>"},
  "admissions": [
    {"observation": "../admission-before", "sha256": "<actual-observation-SHA256>"},
    {
      "bundle": "../admission-recovered",
      "sha256": "<SHA256 of admission-recovered/manifest.json>",
      "verifier_bin": "/opt/argus/bin/argus-verify-admission",
      "policy_bin": "/opt/argus/bin/argus-replay-policy"
    }
  ]
}
```

Use the actual production evidence-verifier and policy-replay binary paths from
the build manifest (the names in the example must match the installed build).
The recovered bundle must contain the matching live admission observation.
The assessor calls `admission_evidence.verify` again; a saved PASS label alone
does not establish re-admission. The bundle's run, target, nonce and manifest
hash must match. Native recovery can use another hashed operational observation
instead of a Workload-proof bundle. Do not add a Workload EAR requirement to the
native baseline.

`bound_ms` is the experiment's declared closure window, not a measured guarantee
derived from the watchdog setting. Same-boot monotonic time is used where
available; cross-host comparisons use wall time and the supplied measured error.

```sh
python3 fact_receipts.py --manifest continuous/manifest.json \
  --result continuous/result.json --receiver server/receiver.jsonl \
  --context continuous/receipt-context.json --output continuous/receipts.json
```

Each fact returns `result`, `received`, `attempted_delivery`, `reads`, and
`phases` (`no_fault`, `before_bound`, `pause`, `recovery`, `boundary`, `unaffected`). A positive
forbidden read remains FAIL despite missing later telemetry. A complete covered
window without a forbidden read can PASS. Missing attribution, absent actual
admission, clock-boundary uncertainty and gaps remain UNKNOWN. No task transport
attempt and no read is NOT_RUN, not successful interception.

For an interrupted run, already observed violations are retained even when the
native completion timestamp is missing. An explicit `observation_end_at_ms`
defines the collected window; without one, only the observed prefix is available
and the unobserved tail remains UNKNOWN. `observation_window` records which end
was used. A run that never started remains NOT_RUN.

`interception_success` is deliberately narrower: a real local-block transport
event for that task must occur in the post-bound pause before re-admission,
with complete observation and no received frame. A failed request or an empty
response by itself does not prove which component blocked delivery.

Outputs include HTTP bytes, complete reads, distinct facts, duplicate complete
reads and partial-frame candidate bytes. Candidate bytes are never computed by
subtracting complete facts from arbitrary HTTP body bytes.

Revision 1329 separates the two paper outcomes. Each read has `scope` and
`reason`; `stop_condition` distinguishes `supervision_stop` (Helper freeze/exit)
from `instance_condition_stop`. `whole_window` and `post_bound` expose
`post_stop_condition_complete_fact_reads`, `post_stop_condition_unique_facts`
and `post_stop_condition_body_bytes`. The legacy `forbidden_complete_fact_reads`
key retains this stop-condition meaning; it does not prove invalid launch history
or an unadmitted replacement. Unknown fault types remain UNKNOWN. Reads by a
different, positively admitted instance do not inherit the old instance's stop
condition; legal re-admission starts a separate interval.

`unadmitted_replacement` is independently reported and currently always returns
UNKNOWN with null confirmed counts. The current E1 observation establishes
observed ADMITTED or UNKNOWN; it does not establish independent policy eligibility
for every comparison group. Old-binding rejection alone does not establish an
interval in which another receiver is unadmitted. Unassociated reads remain
`admission_unestablished` with candidate counts. Complete coverage and positive
admission association are retained in the separate `positive_admission_association`
field; that zero is not a confirmed zero of policy-ineligible reads or evidence
that a replacement attack was attempted. Context `eligibility_intervals`, including
hand-written `eligible=false` or `status=DENIED`, are UNSUPPORTED and never change
the receiver verdict. Do not fill the abstract's replacement result from the
Helper-freeze stop metric.

### Minimum independent eligibility input contract (not implemented)

An online DENIED/invalid-interval adapter must be added and verified before
confirmed nonzero or zero replacement counts can be reported. It must provide:

1. The run, exact container/launch/PID/starttime/boot instance key, common approved
   policy ID and artifact digest, and pinned verifier/build/trust configuration.
   A baseline's own SVID or Ready result is a separate operational observation.
2. Original challenge/nonce, target-bound current evidence, authenticated history,
   signed appraisal result and deterministic production-policy replay establishing
   DENIED; or a trusted, positively observed instance-condition invalidation with
   its precisely scoped reason. A timeout, missing ADMITTED row, mismatched old
   registration or operator-written label is insufficient.
3. The verified association between that evidence and the actual receiver's
   protected process binding, plus the affected admission/use epoch where needed.
   A logical SPIFFE ID alone does not distinguish a replacement process.
4. Actual start/end observations with clock domains and measured uncertainty.
   Re-admission ends an invalid interval only after that instance's fresh,
   positively linked evidence. Missing endings or boundary-overlapping reads
   remain UNKNOWN rather than using planned fault/recovery times.
5. Hashed originals and a verifier that rechecks the cryptographic/policy/instance
   links, rather than trusting a saved PASS/DENIED result. The context selects
   that pinned input; it cannot choose a verdict by boolean.

Once implemented, a complete trusted READ wholly inside a positively established
ineligible interval must produce FAIL and a nonzero confirmed count even when
coverage elsewhere is UNKNOWN. Proving zero additionally requires attempted
releases, full reader attribution and complete coverage of the requested interval.
Current archives lack the complete positive negative-decision chain, so this
delivery deliberately does not create an online DENIED oracle.

For the same process instance, a post-fault observation establishes re-admission
only by comparison with a known pre-fault nonce or Helper invocation. Re-observing
an old identity is insufficient, and a missing baseline leaves
`readmission_unestablished`. A different process/launch requires its own complete
positive admission observation; it does not inherit the previous target's record.

`last_complete_fact_read`, `last_stop_window_fact_read`, `last_body_read` and
`last_stop_window_body_read` retain timestamp, clock interval, request and
instance association. The stop-window fields include pre-Delta reads after the
fault and exclude positively re-admitted reads. A last observed read is not by
itself a cessation guarantee: report coverage, observation end and incomplete
windows alongside it. Measured maximum delay is not a theoretical upper bound.

## Actual Quote generation and subscription identity

The existing Provider UDS exposes `GET /ra/v1/quote-counters`:

```sh
curl --unix-socket /run/argus-workload/evidence-provider.sock \
  http://localhost/ra/v1/quote-counters
python3 lifecycle_evidence.py quote-snapshot \
  --provider-socket /run/argus-workload/evidence-provider.sock --output before-quotes.json
```

Response schema is `argus.quote-counters.v1`: `provider_instance_id`, `agent_id`,
`captured_at_ms` and separate `node`/`workload` `{attempted, generated, failed}`.
The generation boundary includes Quotes later discarded because the history or
target changed. No new Quote is requested by reading counters.

Add `provider_socket` to an existing lifecycle-trial configuration to collect
before/after snapshots. `quote_generated` is separate from existing Node
`quote_samples` (evidence returned to the plugin). A process restart, missing
counter or an in-flight generation at a snapshot boundary is UNKNOWN rather
than a fabricated zero. Helper subscription begin/end and SVID-publication logs
carry `subscription_id`, the existing Helper invocation ID. Credential updates
on that subscription retain the ID; a new Helper subscription has a new ID.

## Recovery milestones

The existing finite lifecycle observer now records `entry_ready` transitions
with target and Helper invocation. `recovery.milestones` reports independently:
`recovery_command_started`, `storage_ready`, `admission_completed`, `entry_ready`,
`first_compliant_read`, and `first_task_completed`. The command stage comes only
from the hashed native continuous result's actual control invocation; a started
command does not imply successful recovery. Missing stages remain UNKNOWN. Admission observation
completion is a conservative timestamp, not the exact EAR issuance instant.

`recovery.anchor_at_ms` is the actual recovery command start. Each observed stage
includes `elapsed_from_recovery_command_ms` as an uncertainty interval. Stages
before that command cannot establish recovery; when the command is unobserved,
command-relative recovery remains UNKNOWN. A task already running at the command
can count as the first completed task if it subsequently has a compliant read
bound to fresh admission and then passes its task/deadline score. Adjacent-stage
intervals compare observation timestamps, which can overlap or appear out of
order; they are not exact internal service durations.

For a pre-existing persisted record with a known content hash, one local read
can establish the storage stage without exposing a new experimental fact:

```sh
python3 lifecycle_evidence.py storage-ready --config /etc/argus/workload.json \
  --url 'http://127.0.0.1:1933/api/v1/content/read?uri=<existing-record-uri>' \
  --api-key-file /secure/openviking-user-key --expected-content-sha256 '<content-sha256>' \
  --run-id trial-a --output server/storage-ready.json
```

Use the actual checked backend listen port. This optional probe requires direct
local-backend access and records content hashes only. If the deployment does
not expose that local route, leave the storage stage unmeasured rather than
opening another port. It does not establish client authorization or successful
Agent task completion.

## Independent E2 connection payloads and socket observations

```sh
python3 connection_facts.py --output private/e2-payloads --seed 7 --requests 200
```

Set `probe.payload_plan` in `fault_trial.py` configuration to that directory's
`payload-plan.json` and use POST to the existing `/api/v1/search/find` endpoint.
Every new-connection request, old-connection request and the single slow
in-flight request uses a different fact. The in-flight body's complete fact is
near its end, so a first-read-triggered fault does not reuse a fact already sent
by another lane. Payloads are used once and never wrap around when exhausted.
Choose enough requests to cover the configured duration; existing baseline and
coverage requirements continue to apply.

Request and response-chunk traces record actual `socket_id`, local/peer socket
addresses, peer identity/serial and connection count. The old lane disallows
automatic reconnection. EOF, reset and timeout observations are separate;
timeouts do not prove peer closure. These are E2 transport microexperiments,
not substitutes for real Agent memory tasks.

`fault_trial.py` now launches `connection_facts.py probe`, a finite wrapper around
the existing transport probe. It subclasses its actual send boundary while keeping
the existing TLS pinning, HTTP implementation, lane scheduling and reconnect rules.
Its `releases.jsonl` records the first frame-prefix fragment passed to transport
per request, with the actual socket-write start/return interval and clock domain.
Split-prefix recognition retains the first fragment's original clock; repeated
attempts use the earliest actual release, not the last successful request. A write
that raises may have partially sent data and is UNKNOWN. A damaged or unfinished
release stream cannot prove first release. The prefix matcher logs only fact IDs,
hashes, lengths and clocks; it does not log request bodies.

This E2 boundary is **the controlled experiment driver passing a fact's first
fragment to transport**, not the Agent first learning that fact or the service
receiving it. Socket-write return does not imply receiver delivery. Actual ASGI
READ remains the independent receipt boundary. Payload creation, `planned_at_ms`,
`offered_at_ms` and request-start timestamps cannot substitute for release.

For continuous tasks, the different release source is `gateway_agent_dispatch`:
`result.steps.released_at_ms` must equal the matching Gateway `release_receipt.at_ms`
at `openclaw_cli_input`, linked to task/fact/work-item/session and prompt digest.
Missing receipt means UNKNOWN even if controller dispatch intent exists. That is
Agent-input dispatch, not a socket write or model-provider receipt. The assessor
keeps these sources separate and does not merge them into one first-release clock.

`whole_window.release_classification` and `post_bound.release_classification` add
four groups, each with complete-read, unique-fact and post-stop violation counts:
`pre_fault_released_late`, `post_fault_first_released`,
`boundary_or_missing_release`, and `pre_fault_read`. PRE requires release wholly
before fault-command start; POST requires release and read wholly after actual
fault-command completion, including measured clock error. Overlap, missing fault
completion, contradictory chronology or absent release evidence remains UNKNOWN.
The existing `post_stop_condition_*` and `forbidden_complete_fact_reads` metrics
retain their read-time meaning and compatibility; a known READ/FAIL is not removed
because first-release classification or later coverage is UNKNOWN.

The fact/collection `result` is the receive/stop-condition verdict. It is not a
combined certification of first-release completeness or independent instance
eligibility: a conforming observed read may retain PASS while `first_release` or
`unadmitted_replacement` is UNKNOWN. Report these three axes separately.

The default coordinator collects a hashed `fact-manifest.json`,
`fact-native-result.json`, `fact-context.json`, `releases.jsonl` and
`fact-receipts.json` alongside its existing trace/fault/receiver snapshot. Optional
`receipt_context` points to the existing hashed admission context; omission leaves
admission association UNKNOWN while complete READ and first-release evidence are
still reported. Legacy unframed `body_file` traffic retains transport assessment
but cannot produce synthetic-fact counts. Resume collects existing observations
and never resends a fact or injects another fault.
