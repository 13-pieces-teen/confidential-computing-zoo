# Argus 代码收缩与闭环计划

状态：本轮收缩已落实到代码、测试与运行文档，未提交或推送；真实远程验收仍为 NOT_RUN。基于 `8be8afe` 及当前未提交的第 4—7 项扩展。当前结果见 [VALIDATION.md](argus/VALIDATION.md)。以下保留取舍理由与实施范围。

## 1. 目标与取舍标准

只围绕三件事建设：服务实例符合策略才可取得通信资格；实例或监督失效后由 Argus 关闭交付入口；多个独立 Gateway 使用同一服务时身份与私有业务范围相互隔离。

实验代码用于证明这些行为。实验操作者与受信管理组件沿用现有信任假设，不新增“防止有 root 权限的实验操作者伪造整套实验”的目标。工作负载自报身份仍不可信，实例来源须独立核对；危险操作仍须绑定明确的目标，避免误伤其他实例。

新增一个阻断条件前，必须能指出目标范围内的具体反例。保护凭据、阻止重复创建、避免操作错误实例值得阻断；无关实验组没构建、性能负载未冻结、审计暂时不可用，不应阻断功能验证或业务本身。

保留 `CanReattest=false`、现有批准策略、实例级粒度，以及 Argus/业务授权分工。不新增 TCB UpToDate、任务授权、SPIFFE 与 API key 强制映射或 Agent–Agent 编排。

## 2. 产品路径保留，实验路径收缩

| 模块 | 本轮决定 |
|---|---|
| Node/Workload 证明、历史核验、Broker、Helper、readiness、NGINX/AuthZ | 保留现有职责与必要失效关闭，不为缩短代码撤销安全边界 |
| `fleet.py`、部署适配、`fleet_business.py` | 保留独立身份/目录/组/选择器、私有用户、真实 API 负例及六阶段业务结果；不增加能力发现、权限引擎 |
| `runner.py`、`suite.py`、`step.py` | 原地简化，不另造执行器；只检查当前选中 case/group 的依赖 |
| `common.py`、负载与资源日志 | 区分操作检查点与测量日志，取消普通测量每行 fsync |
| `trusted_runtime.py` | 移除自定义 `__import__`/`exec` 模块加载图，改为每个工具进程只运行一个明确安装包 |
| `variants.py`、静态客户端 | 保留已有五组与实验产物隔离，按需运行；暂不重写为插件系统或另一套静态客户端 |
| receiver 与接收判定 | 改为不控制业务的观测工具；补在途请求，按受影响区间判定 UNKNOWN |
| 原有 `resume-launch`、业务 journal | 保留为对应操作的恢复事实来源，不新增恢复协议 |
| 离线历史诊断、LoCoMo 转换、图表 | 保留现有独立工具，移出首轮默认路径；暂停继续扩展 |

## 3. 先取消不必要的运行门禁

- 仅 E5 性能测量要求冻结 pilot load。E1/E3/E4 可以没有性能配置。
- `--run-id` / 所选 case/group 的预检只覆盖它们实际依赖的产物。正式对照运行仍检查该组实际生效配置和隔离身份。
- 继续保留一个 manifest、一个执行状态、业务自己的 journal 和薄结果回执。不增加数据库、多层账本或通用工作流系统。
- 只读查询可以有限重试。中断测量标为 `interrupted`，允许显式创建新 attempt，从预热重新开始；旧目录保留、禁止拼接窗口。
- 不按 `measure` 名字推定无副作用：默认 GET 压测可重开，带业务写入的 POST 仍执行写入规则。未知提交、未知创建、未知故障操作不自动重放；已知操作继续查询。
- 统计保留所有 attempt 状态。正式性能轮次若中断，整轮不纳入完整窗口统计；重跑使用相同配对设置，报告重跑及缺失，不挑选最佳结果。

`runner.py`、`step.py`、`fault_trial.py` 不再全部丢弃错误输出。复用一个有大小上限的诊断路径，记录阶段、错误类型、退出码和脱敏原因。已知业务 stdout/正文不收集，API key、令牌和完整提示词不进入日志。子进程超时仍有固定期限和清理，不为诊断增加无限等待。

## 4. 持久化按用途处理

| 数据 | 行为 |
|---|---|
| 提交/创建/故障之前的意图、已知操作 ID、恢复状态 | 保留原子写入、必要 fsync、操作锁 |
| 压测请求与资源 JSONL | 缓冲写入；正常结束 flush/fsync 后再写完整标记与摘要。异常退出保留原始数据，该 attempt 不作完整测量 |
| 结果回执 | 关联运行/操作与原始结果摘要；保留已有校验，避免旧 PASS 或丢失源文件被复用 |
| 接收审计 | 独立采集进程批量持久化，缺失区间未知；不追求崩溃瞬间无损 |

压测完成回调不应在释放并发槽之前等待磁盘 fsync；采样线程也不应因逐行刷盘降低实际到达负载。无需新增通用日志平台。

## 5. 接收审计只观测，不成为额外准入门禁

这是对上一版“逐次读取等待持久 ACK”设计的明确调整，不能仅当作无语义变化的优化。

- 保留薄 ASGI 包装、独立 collector、元数据限制、请求/分块序号与实际进程关联。
- 移除业务路径中的同步 ACK 等待，以及因 collector 不可用而抛出的业务异常。读取事件通过非阻塞 Unix datagram 发送，发送失败记录丢失计数；不建设重传或持久队列系统。
- collector 使用内核提供的发送进程凭据，结合 PID/starttime/cgroup 和已有实验部署记录，关联原实例与替换实例。观察“尚未获准但实际读到数据”的替换实例，不等于为它授予 Argus 身份。
- collector 批量刷盘，正常结束完成最后一次同步；源序号、水位和丢失计数用于划定覆盖区间。无法证明完整覆盖的区间为 UNKNOWN，包括崩溃后的尾部。
- 一个请求中断不自动废弃整轮其他完整区间。来源明确的确定违规仍判 FAIL；无法归属或缺失的记录不能推导零接收。
- collector 崩溃/退出不能停止业务。生产中的 Helper、AuthZ、凭据检查和 NGINX 关闭行为不变。

接受这一取舍：审计更轻、归因更清晰，但崩溃附近可能保留未知区间。不为消除所有 UNKNOWN 增加内核探针、第二套认证或新的信任服务。审计开销仍单独测量。

## 6. 补足最小且关键的交付验证

`remote_acceptance.py` 保留旧 TLS 与新 TLS 两条探针，再增加一个故障前开始、故障后继续发送的分块请求。先确认服务端已经读取首块再注入故障。

接收判定按服务端读取时间与字节数计算，不再用请求开始时间排除在途请求。使用明确的停止界限和时钟不确定区间；越界的确定读取判 FAIL，无法定位的区间保留 UNKNOWN。

正常 NGINX 缓冲设置不偷偷修改。若业务路径无法形成持续应用读取，记录该场景不可执行；另行启用流式诊断时，各组使用同一设置，并与正常业务路径结果分开。

E2 的一般业务门禁先用已完成的非空提取和双连接基线。分块场景额外等首块读取。不新增模型内部暂停、任务步骤授权或通用断点系统。

## 7. 移除运行时加载器的额外复杂度

`fault_fixture.py`、`lifecycle_evidence.py` 以明确安装包中的独立进程运行，避免同一解释器混用生产/其他实验组模块。复用现有 CLI 和 JSON 输出；仅对确实缺少的只读信息补小型接口。

删除 `trusted_runtime.py` 的私有导入图。安装/预检负责源码及构建清单；操作前核对配置指向的安装包、实验标识、unit 和目标实例。故障操作继续限定实验目录、准确容器/进程，并保留恢复记录。普通只读采样不再重复核验整个 Python 源码目录树。

不在本轮顺便重写所有字符串变体生成逻辑；先保留已有有断言的定点修改，消融生效检查仍保留，尤其是 −Close 的全部主动关闭来源。

## 8. 实验按问题选择，避免默认全矩阵

默认先跑完整 Argus：单客户端一个种子，再三客户端一个种子。它们是 smoke 验证，不作为论文统计。

| 正式实验 | 按需启用的组 |
|---|---|
| E1 联合准入 | full、native；离线三规则独立报告 |
| E2 失效与交付 | full、−Watchdog、−Close |
| E3 复用与恢复 | full |
| E4 三客户端私有记忆及故障范围 | full；比较业务开销时再加入 native |
| E5 成本与规模 | full、native、static；审计 on/off 单独配对 |

正式机制实验十个种子、性能 1/2/4/8、预热 30 秒、测量 120 秒、五轮保持原定义；只在选择对应正式实验时展开。静态组准确标为“同适配器/本地实例约束下的静态证书对照”，不宣称裸 mTLS 成本下限。

不再宣称 E1—E5 已全自动编排。先提供三条固定端到端操作：实例准入反例、故障后接收观测、三客户端私有记忆。复用现有命令和少量场景配置，不先建设通用多机编排。

## 9. 实施顺序与停止条件

1. 简化选中项预检、恢复分类、诊断和普通测量刷盘，保持现有命令可用。
2. 将接收审计改为纯观测，完成局部 UNKNOWN、替换实例关联和在途分块判定。
3. 移除私有导入器，验证独立进程不会操作其他实验组或生产服务。
4. 接通三条固定场景，收缩默认配置与文档；现有基线和离线工具保持可选。

本地验收只增加与改动直接对应的检查：功能验证无需性能配置；其他组缺失不阻断选中组；中断测量可新开且不混样；未知写入/故障不重放；错误可定位且不含秘密；日志不逐请求刷盘；collector 停止时业务继续且证据变 UNKNOWN；局部缺口不污染完整窗口；在途越界读取和未准入替换实例能被观测；故障目标隔离保持。

以上通过后停止新增基础设施，等待远程按单客户端→三客户端→故障→相应对照→性能验收。真实 TDX、系统关闭时间、模型业务和跨机性能继续记 NOT_RUN，直到有真实结果。源码/构建清单在实际实现完成后重新生成；本次仅新增规划文档。
