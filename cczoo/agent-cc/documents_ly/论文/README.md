## 2. 当前写作口径

- **研究对象**：Agent 与 Agent Service 的可信服务组合。服务可以属于同一组织或不同组织，也不要求接收方是自主 Agent。
- **三个研究问题**：准入依据、交付落实、运行维护。它们组织论证；框架中的 C1–C3 是候选贡献记录，Evaluation 中的 RQ 是实验问题，三者不逐项等同。
- **方法流程**：分层准入与取证、证据和策略核验、身份与实际入口关联、正常业务复用，以及可观测失效后的停用和重新准入。方法组织维护在框架 §3，协议和实现事实引用目录外的专题文档。
- **当前评价**：OpenViking 的 τ²-bench 适配、LoCoMo/OpenClaw、Server 混合负载；分别观察任务、问答与服务性能，并配合实际交付、生命周期、强基线及消融实验。
- **扩展候选**：跨企业诊断与核验、其他数据集、更多 Agent 运行时和服务类型、证明状态参与 Agent 决策、敏感交付时按需核验。按实际完成情况纳入，不由整理动作升级为已有能力。
- **贡献与结果**：低侵入、复用价值、额外 Workload Quote 的作用和性能影响均需要比较支持。真实硬件 PoC、软件回归和完整 Agent 任务分别引用，评价计划不能替代正式结果。

## 5. 更新规则与尚需完成的写作

1. 主问题、Story 和中文引言改叙事稿；章节、pipeline、候选贡献和结果位置改框架，避免另建同主题的独立主稿。
2. 基线、统计和 E1–E7 的统一规则改总方案；任务接入、计时与判定细节改实验细化文档。完成项在 Review 中附证据，不因计划写好而标记通过。
3. 新文献的来源及机制填汇总表；它对贡献主张的影响写入重叠审查。缺少原文信息不推导为对方缺少能力。
4. 场景和早期方向保留原路径，标明其用途及日期；需要采用的内容再并入主稿，不把历史优先级直接转为当前待办。
5. 新结果写入带版本、环境与日期的验证或实验记录，主稿与本目录仅引用；保留失败、阻塞和未执行边界。

当前已有 Story、引言和章节骨架；完整英文方法、实现、评价结果与最终贡献段仍需继续形成。正式性能与强基线结果、完整任务证据和所声明的复用范围，按实验方案落实后再写入正文。
