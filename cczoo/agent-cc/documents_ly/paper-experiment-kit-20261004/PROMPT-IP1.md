1. 核对实际 Node/target 元数据，按契约配置精确 Entries、控制材料和路由。角色变化不作为放宽 selector、身份或权限的理由。
2. 验证当前实例的合法 mTLS 业务访问，与 IP2 的 Quote、链、登记和入口原件关联。这是新环境的部署就绪检查，不重跑整个 P0。
3. IP2 若交付新的 E4 profile，核验其为 Full 正常/恢复两条件、单 Gateway、六步任务；确认两次 pilot 与六次正式任务分开。只同步确需使用且已测试的适配文件，不覆盖既有 P0 修复。
4. 模型与 Embedding 沿用已选 SiliconFlow、deepseek-ai/DeepSeek-V3.2 和 Pro/BAAI/bge-m3；密钥从本机受保护配置读取，不回显。模型请求进程沿用取消公司代理的设置，控制端网络单独保持原配置。本批次固定这些条件。

## 按 IP2 的批次调度执行

- E5 + E3：Full/native、实际新建/复用 TLS，每条件三轮；每轮预热30秒、测量120秒。记录每轮 p50/p95、全部请求结局、负载配置；同步观察自然换证和 Quote，不为计数触发额外认证。与 IP2 约定资源采样组件和时间窗口。
- E2：为配置变化与 Helper 冻结两类故障持续发送可关联的合成新事实，保持冻结的负载和窗口。HTTP 状态记录访问；应用是否实际接收由 IP2 独立 receiver 原件确认。
- E4：三个固定种子分别运行 Full 正常/恢复条件，共六轮完整任务。保存六步结果、全部确认提案、真实回读、正确继续、完整完成和恢复耗时。判定任务约束与记忆使用，允许自然语言前导文本；实验内容判定器不加入 Argus 准入链路，不向模型提供答案或重发未知写入。
- E1：收到具体窗口与 attempt 关联约定后，先启动有界采样并回 READY，再由 IP2 执行 A/B/C。按实际时间、target、request ID 及证书签发/轮换关联，不用事后探针补历史窗口。

## 批次完成与停点

每批交付原件索引及你的数据分片；IP2 合并唯一 results.json，你核对客户端部分。保留预定运行的真实结局，同一运行可引用到多个指标，但不增加样本数。试验性 pilot 不混进正式统计。

服务端未就绪时，完成客户端准备、归档核对和离线结果复核，交付一份明确依赖清单；不自行启动新 guest、修改内核或恢复冻结链。已就绪时按约定批次继续，无需每个检查点等待用户确认。遇到新权限/资源缺口或协议未定义的未知写入，报告具体阻塞；已完成且独立的工作继续收束。
