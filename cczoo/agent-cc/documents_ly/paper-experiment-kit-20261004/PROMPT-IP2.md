# 给 IP2 的执行 prompt

请继续 Argus 论文实验，按同包 EXPERIMENT-PLAN.md 执行。你负责服务端、最小工具适配、串行调度和结果汇总；IP1 负责客户端、控制端及独立观测。材料 Git 提交与运行代码版本分别记录。

## 先取得材料并核对环境

1. 按 GIT-GET.md 导出用户指定提交，核验 SHA256SUMS。保持实际运行分支与未提交修复。记录当前 HEAD、构建摘要和补丁状态；不得把本材料分支的旧基线源码部署到主机。
2. 实测核对服务端可用性，不用历史回执宣称当前 ready。若已有通过完整链路检查的新服务环境，直接进入部署就绪核验。
3. 旧链及未知 INFLIGHT 保留原状与原件，不清库、清 fence、手填成功或重放未知 stop。未完成的 genesis 不当作已确认链沿用。
4. 若缺可用服务端，优先在原已验证 TDX 平台和已知工作组合上，按既有授权及正常 provision 流程准备干净环境。新 boot、新链、新 owner material 按新实例处理。不要求旧故障 guest 与新环境永久同时在线；旧环境退役须满足已批准的归档/保留安排。
5. 本实验任务不继续扩展内核升级、移植或启动参数试验。缺平台控制权或可用镜像时，一次性说明最小资源依赖；继续离线工作与工具适配，不重复尝试不稳定 guest。
6. 部署就绪必须具备真实 Quote/评估、完整已确认链、pending=0、当前进程登记、身份发布、入口、独立 collector，以及 IP1 的实时合法业务访问。TDREPORT/RTMR 接口检查不能代替该核验。P0 原结论保持，不重跑整个 P0。

## 环境准备期间完成最小适配

先核对现有版本是否已实现以下事项；缺什么补什么，逐项说明目的。只在自己的最新修复之上改动，提交并交付明确差异及相关测试。

- E4：新增显式恢复案例 profile，Full only、healthy/recovery、单 Gateway、六步任务。两条件各一次 pilot；正式三个固定种子配对，共六轮。保留原四条件 profile 校验。测试新 profile 的完整配对、缺条件拒绝和六步/单客户端约束。
- E5：正式重复数固定三轮，保留 Full/native、两种真实连接模式、同 API/数据/权限/负载。
- E1：保留已修复的 Provider INFO、SPIRE 包装日志和 journald MESSAGE 整数数组解析，先采证再操作。远端探针由 IP1 用实时身份执行。
- 文档与配置：更新当前执行入口，避免旧轮次/旧依赖误调度。新 profile 未部署前不启动 E4。
- 离线规则：在归档副本上运行已实现的规则案例，区分 archive 与 signed_fixture，保存实际判定和首次拒绝层。此结果写 history，不填写为在线 A/B/C 样本。

本材料包仅提供设计、结果接口和绘图程序，不替换准入验证器，也不意味着上述执行器适配已部署。

## 双方就绪后单线执行

顺序：E5健康负载＋E3自然轮换 → E2两项定向消融 → E4任务 → E1在线等待/确认 → 汇总。

每批开始前固定版本、配置、输入、顺序、采样窗口和时钟关联；需要客户端观测的动作，先收到 IP1 READY。通过既有受保护目录直接协调，不要求用户逐阶段传话。测量期间不并发运行其他正式负载或绘图分析。

1. E5 + E3：Full/native × 新建/复用TLS × 三轮，预热30秒、测量120秒。由 IP1 发负载，你采服务端资源及身份/Quote 原件。成本统计覆盖同一窗口的全部请求结局。
2. E2 配置变化：Full/no_close 三对；E2 Helper冻结：Full/no_watchdog 三对，共12个故障运行。注入限实验组，保留业务容器、持久卷、链和独立 collector。记录后端存活、观测覆盖、应用实际读取、检测和关闭时刻。窗口内未关闭记右删失与实际时长，不填0秒；恢复后经过必要核查与重新准入再开下一轮。
3. E4：pilot 通过执行准备后，按新 profile 跑六轮正式任务；故障用可恢复的 Helper 冻结。保持确认状态、真实读写与必要重新准入，不自动重放未知业务写入。与 IP1 关联首次合法记忆访问及正确继续。
4. E1：到本阶段再核对 OIDC、delegation 和策略的剩余有效期。在线 B 固定在 Docker 完整成功响应已取得且结果可靠保存后的受支持 before_confirm；不再先额外 stop 容器清场。A为合法准入，B为成功结果等待记录确认时的新准入，C为原操作确认后的独立准入。先各模式一次工程 pilot，再冻结三对正式 A/B/C 轨迹。若准备操作出现未知结果，按实际位置结束该轨迹；不重放、不计作预期B拒绝、不擅自仲裁。

## 汇总与交付

你维护唯一已填写的 results.json，放在证据输出目录，保留材料中的空白模板。合并 IP1 分片并核对原件；每项使用实际 run_id、evidence_ref 和实际样本数。未知留 null，所有预定运行的真实结局保留；正常处理、人为等待、离线核验分别计量。

每批执行 validate_results.py 并更新结果索引，IP1 复核客户端部分。绘图可在独立分析环境或实验空档完成，无需为渲染升级运行服务环境。

最终交付：适配代码提交/补丁及测试、环境与版本清单、完整运行索引、结果数据、图表和原件引用。P0/A3 保持原版本结论。遇到阻塞，继续完成不依赖它的工作并给出一个具体依赖；不循环重跑挑选通过样本，不为填图扩充实验。
