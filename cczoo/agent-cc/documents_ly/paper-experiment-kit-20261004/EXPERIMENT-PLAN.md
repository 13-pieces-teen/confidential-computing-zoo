# Argus 后续实验：围绕论文主张的收敛方案

版本：2026-10-04。本文件是新的实验设计与交接方案，尚未部署到 IP1/IP2。论文方法与远端执行分开验收；现有运行状态来自用户交接，未在本轮登录主机核验。

## 1. 论文应当回答什么

本文的主线是：智能体持续向外部记忆披露新上下文，因而需要把“允许通信的服务身份”对应到“当前具有接收资格的服务实例”。Argus 用实例证据与生命周期记录建立准入依据，再通过代理绑定、监督和主动关闭维护后续交付；合法恢复后，智能体从已确认记忆继续任务。

实验对应三项优势：可核验的实例准入、失效后的交付控制、确认状态上的任务继续。成本说明这些机制的部署代价。保留 E1–E5 编号和四个 RQ，减少独立执行批次。

比较目标为相同本地保护下的准入判据，以及关闭/监督机制的因果作用。E4 是部署案例，衡量恢复正确性；E5 在固定业务负载下衡量附加成本。主线不承担模型能力排名、任意故障自动恢复、虚拟机跨重启历史连续性或全链扩展性主张。

## 2. 已有结果怎样使用

| 材料 | 在论文中的职责 | 后续操作 |
|---|---|---|
| P0 / P0-D PASS | 验证已固定实现的业务路径与权限前提 | 保留原版本、原件与结论；新环境另做部署就绪检查，沿用通过的权限规则 |
| Full A3 CLOSED / PASS | 真实合法准入及客户端业务访问的集成证据 | 引用原 attempt；独立于未来版本/拓扑的配对样本 |
| 未形成 B 的 stop / EOF / INFLIGHT | 解释该 attempt 的执行范围和当前环境处置 | 归档诊断，B/C 保持 NOT_RUN；不可改称预期拒绝或恢复成功 |
| 新 guest 的启动与内核诊断 | 环境部署材料 | 从论文实验执行清单移出；不计作 E1/E2 样本 |

P0 不重跑意味着通过的历史验收保留。更换服务 guest 后仍需核实新实例的 Quote、链、身份、入口与实际业务访问；这项就绪检查不是重做整个 P0，也不能用旧 P0 的证书或 PID 代替。

### 为什么 E4 减为 6 轮

原方案 Full/native × 正常/故障两组均保留相同本地关闭，E4 的故障因而主要检验任务如何应对服务中断与重新准入。E1 已比较两组的准入判据，E5 已比较成本；在 E4 再做整套 native 任务不直接隔离新的机制。本轮把 E4 定位为 Argus 的恢复案例，保留正常对照及 3 个固定种子，共 6 轮。相应论文主张是“支持确认状态上的任务继续”，不再承诺较高的跨系统完成率。若以后要提出后一主张，再预先设计有明确处理差异的任务对照。

### E1 的关键改动

在线注入点固定为完整 Docker 成功响应已经取得、结果已经可靠保存之后的 `before_confirm`。核查该版本真实状态为可续交的 `RESULT_READY` 或 `SUBMITTED`，并关联同一 mutation 的完整结果和成功目标；随后保持记录未确认、发起新订阅、释放确认并独立重新准入。它是“记录等待”的实验，不是任意崩溃恢复实验。

不再为进入 B 预先额外执行一次 Docker stop 来清场。由现有受支持 launch/start 流程准备目标，各次生命周期操作均须完成其正常确认；需要停止服务单元时先核查 unit 依赖是否会实际 stop 容器。若必要的准备操作出现未知结果，该运行按真实位置结束，不重放、不将它统计为 B。

Full/native 保留等价当前检查、业务权限及本地保护。native 若被共同检查拒绝，报告共同保护；历史规则的独立增量需要相同当前条件下的可达差异。离线签名案例可以解释规则，不代替真实在线对照。

### E2 / E4 的关键改动

选择可恢复的配置绑定变化及 Helper 冻结，保留业务容器、原持久卷和记录链。避免把应用恢复与未知 Docker 结果仲裁绑在同一轮。E2 每次确认后端仍可用、采集器覆盖完整，按实际接收计数。E4 沿用六步任务、Proposal/Decision、真实回读及独立判定器；判断约束和记忆使用，允许自然语言前导文本。Argus 的准入路径不参与内容判定。

E4 的恢复仍经过必要核查与重新准入。正常、拒绝、超时、未知和未派发分别记录；完整任务成功与在全部已确认提案上正确继续分别展示。控制器不提供模型答案、不重发未知写入。

### 从本轮必做清单移出的项目

全部生命周期崩溃切点、未知结果强制仲裁、跨 guest 重启链连续性、新内核兼容实验、双服务共享待决、通过大量真实生命周期操作形成三点历史增长。旧材料与工具保留用于复现；本轮的论文方法同步去除这些实验承诺。影响核心机制的实际失败仍保存在结果索引及对应实现范围说明中。

## 4. 两台机器如何回到实验

### 先区分三台 guest 与两台物理主机

IP1 是客户端和控制端的负责人：保留现有 OpenClaw guest、SPIRE Server、Trustee 和必要隧道。OpenClaw 这一路径使用其现有身份协议，本轮不要求为它安装 RTMR 驱动或换内核。

IP2 是服务端的负责人：OpenViking、TruCon/Docktap、Provider、Helper、入口和 collector。原服务端的已知工作组合曾完成 P0/A3，但当前旧链被冻结；IP1 宿主上后来新建的服务 guest 则尚未完成稳定 bootstrap。新服务 guest 的内核问题不能归到 OpenClaw 客户端。

### 现在能立即执行的工作

1. 两侧核验既有交接包，固定 P0/A3 的来源与实际结论。停止已完成窗口、与当前取证无关的重复 sampler/watcher；按具体 unit/PID 停止，保留控制服务和未封存的易失状态。
2. IP2 在归档副本上跑离线规则案例，IP1 核对场景定义、判据和结果索引。此工作无需启动新服务 guest。
3. 两侧各自准备新实验配置与原件交接清单；不再要求每个阶段由用户转贴一次回执。

### 在线实验只需要一套可用的服务端基线

优先在原 IP2 所在、曾验证可工作的 TDX 平台及相同已知组合上，由有控制权的一方通过正常 provision/rebuild 流程准备干净服务 guest。旧现场完成可信归档后可以退役；不要求故障 guest 与实验 guest 永久同时在线。新的服务端按新 boot、新链、新 owner material、新登记与准入处理，旧 P0/A3 仍是旧运行的结果。

此方案需先确认原平台实际控制权限、原件归档和可用镜像。当前 INFLIGHT 链不能通过删除 DB、清 fence、手填成功或重放 stop 变成这套新基线。若原平台不可操作，IP2 提交一个明确的资源依赖；新宿主上的内核/虚拟机静默停滞继续作为单独环境问题，不以执行 E1 为名扩展试验。

换实验方法能减少后续操作，但不能使被冻结的旧链变为 ready。真实在线结论仍需要一套通过就绪核验的服务端。

### 基线就绪后的执行顺序

**就绪核验 → 健康 API 成本＋自然轮换 → E2 两项定向消融 → E4 两条件任务 → E1 在线等待/确认 → 汇总。**

将会产生记录待决窗口的 E1 在线部分放到最后，使其前提或操作异常不会阻塞其他已经可以独立完成的举证。论文按 RQ 讲述，实际执行顺序按共享环境依赖安排。

就绪核验需有真实 Quote/评估、完整已确认链、无 pending、当前进程登记、身份发布、入口及 IP1 实时业务访问。TDREPORT/RTMR 接口验证不能单独代替该检查。若使用新拓扑或新构建，实测比较在同一新配置内完成；旧 A3 不加入新版本的配对统计。

## 5. 最小实现改动与目的

当前任务完成的是论文和方案修订，以下执行器调整交 IP2 单独实现并交付，避免把未部署配置说成可直接运行。

| 文件/位置 | 最小改动 | 目的 |
|---|---|---|
| `continuous_suite.py` 的 profile 校验 | 新增显式恢复案例 profile，要求 `groups=[full_argus]`、正常/故障两条件、单客户端、六步 typed work-item；原 v1 四条件规则保留 | 支持 6 轮 E4，避免关闭原验证条件来“凑通过” |
| `tests/test_continuous_suite.py` | 覆盖新 profile 的两条件配对、缺条件拒绝、六步/单客户端限制；确认旧 v1 仍是四条件 | 验证实验设计改变而 P0/原四条件协议不变 |
| 新的 E4 pilot/formal 示例 | 2 轮 pilot，3 个固定种子的两条件正式配置；独立目录和用户 | 防止旧 4/12 轮示例继续调度 |
| E5 固定负载配置 | 重复数由 5 改为 3；保留相同两组、两连接模式和冻结负载 | 将纯测量从 50 分钟减为 30 分钟，保持比较对象 |
| E1 采集配置 | 固定 Provider INFO、journald MESSAGE 的字符串/整数数组解析、实时远端 probe、先启动采集再执行 | 沿用已修复的根因，防止采到了结果却无法关联 |
| 原件与索引 | 每轮保存 attempt/mutation、当前 target、实际采样窗口和时钟误差、双方原件摘要 | 支持一批次自动闭环，避免人工反复传话 |
| 文档入口 | README、PAPER-EVIDENCE-PLAN、TWO-HOST-SEQUENCE、WORK-ITEM、RESULTS 模板同步新范围；旧协议标为历史 | 防止执行代理从旧数量/旧依赖启动多余任务 |

不需要为本设计变更核心准入语义、批准策略、CanReattest、身份、业务 API 或 Docker 生命周期恢复逻辑。API key 继续使用受保护配置；OpenClaw/OpenViking 的模型请求沿用既定 SiliconFlow、DeepSeek-V3.2、Pro/BAAI/bge-m3 及应用进程取消公司代理的设置，控制端自身网络配置单独核对。

远端现有修复版本以实际源码、构建摘要和未提交补丁为准。本地并未取得其全部最新代码，IP2 应在自己的最新修复之上做上述小改动，交付明确提交与差异；不要覆盖 P0 修复或把旧本地 checkout 整包替换到主机。

## 6. 最终呈现

主文保留一张准入判定表、一张关闭与实际接收图、一张任务恢复表、一张正常访问成本图；身份复用及分段成本放附录表。图表模板见同包 figures/。每个图表前先说明它支持的主张，再解释机制为何产生该结果。重复日志、部署排错和逐次交接放复现材料；案例的实际判定和影响核心结论的异常保留在完整结果索引。

结论强化“可核验准入—持续接收控制—确认状态继续”的联系。正式数据形成前用方法时态；形成后按真实证据填入条件、效果和样本数。
